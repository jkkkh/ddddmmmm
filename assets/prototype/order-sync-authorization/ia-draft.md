# IA Draft — 私域-公域订单同步授权与绑定

> Phase 0 产出。从 brief 推导，**禁止**套用固定后台页面清单。

## Brief 摘要

- 原文要点：品牌方需在私域（小程序/小店）与公域（直播间/平台）之间同步交易订单；同步前必须获得用户授权并确认公域ID与私域会员号的绑定关系。旅程：公域直播间点击商品 → 私域商品详情 → 登录会员 → 加购 → 支付 → 生成订单。绑定不一致时提示用户确认或更新；用户可随时查看、修改、撤回授权与绑定；支付成功后可靠同步至公域。
- 产品类型：C 端（品牌私域小程序用户端）
- 首批范围（MVP）：商品详情浏览 → 会员登录 → 登录后授权/绑定决策（场景A/C 弹窗）→ 订单确认页常驻同步状态 → 授权与绑定管理入口

## 1. 核心实体

| 实体 | 说明 | 来源 |
|------|------|------|
| 公域ID | 用户在公域平台（直播间、视频号等）的唯一标识 | brief 原文 |
| 私域会员号 | 品牌私域小程序/小店注册会员唯一标识 | brief 原文 |
| 绑定关系 | 公域ID ↔ 私域会员号的一一映射 | brief 原文 |
| 授权记录 | 用户对订单同步的同意记录（含协议版本） | brief 原文（授权协议、协议版本更新） |
| 订单 | 私域产生的交易订单，支付成功后同步至公域 | brief 原文 |
| 授权协议 | 订单同步授权法律文本，有版本 | brief 原文 |

## 2. 角色与目标

| 角色 | 主要目标 | 来源 |
|------|----------|------|
| 消费者（会员） | 不被打断地完成购买；授权/绑定一次即可，随时可查看、修改、撤回 | brief 原文 |
| 品牌方运营 | 统一管理订单、售后与会员权益（后台页面未定义，本期不做） | brief 提及 / 推断·待确认 |

## 3. 关键任务链

### 任务链 #1 — 浏览商品（不被打断）

```text
[消费者] 从公域直播间跳转私域商品详情 → 需要 浏览商品、加购/立即购买（无弹窗打扰） → 建议 c_detail（商品详情页）
```

### 任务链 #2 — 未登录则登录会员

```text
[消费者] 点击购买但未登录 → 需要 登录会员 → 建议 c_form（会员登录页）
```

### 任务链 #3 — 登录后授权/绑定决策

```text
[消费者] 已登录但未绑定/授权 或 绑定不一致 → 需要 在单一决策弹窗中确认 → 建议 c_form overlay（授权绑定弹窗 / 重绑确认弹窗）
```

### 任务链 #4 — 提交订单与同步状态

```text
[消费者] 提交订单 → 需要 订单确认页常驻同步状态 + 未授权时再次授权入口 → 建议 c_form（订单确认页）
```

### 任务链 #5 — 管理授权与绑定

```text
[消费者] 随时查看/修改/撤回授权与绑定 → 需要 管理页入口与操作 → 建议 c_profile（授权与绑定管理页）
```

## 4. 页面映射

| page-id | 页面名 | 服务的任务 | 页型 | surface | 优先级 |
|---------|--------|------------|------|---------|--------|
| product-detail | 商品详情 | 任务链 #1 | c_detail | c_end | P0 |
| member-login | 会员登录 | 任务链 #2 | c_form | c_end | P0 |
| popup-bind-auth | 授权与绑定弹窗（场景A） | 任务链 #3 | c_form overlay | c_end | P0 |
| popup-rebind-check | 重新绑定确认弹窗（场景C） | 任务链 #3 | c_form overlay | c_end | P0 |
| order-confirm | 订单确认 | 任务链 #4 | c_form | c_end | P0 |
| auth-bind-manage | 授权与绑定管理 | 任务链 #5 | c_profile | c_end | P0 |
| popup-protocol-update | 协议更新重授权（场景B 变体） | 任务链 #3 | c_form overlay | c_end | P1 |

## 5. Scope Out（明确不做）

- B 端运营/客服后台（订单统一管理、售后、会员权益）：PRD 未定义需求
- 直播间页：属于公域平台，不在私域小程序内
- 购物车页：授权决策点在结算前，购物车 UI 非本 PRD 范围
- 支付页 / 支付成功页：非授权/绑定相关需求
- 多绑定关系：PRD 明确「需业务确认」

## 推导依据（必填）

页面全部由 PRD 4.1 用户旅程与 4.2 关键决策点推导：浏览 → 登录 → 授权/绑定决策 → 提交订单 → 管理。弹窗是旅程中唯一需要用户决策的节点，故作为独立 overlay 帧（场景A/C）；订单确认页承载 PRD 5.3 的常驻同步状态；管理页来自产品目标「用户可随时查看、修改、撤回授权与绑定」。未按「电商标配八页」添加首页/购物车/支付/直播间——PRD 未定义这些页面的同步相关需求，且直播间在公域平台。共 6 个 P0 帧 + 1 个 P1 变体（复用场景A弹窗结构），避免凑页。
