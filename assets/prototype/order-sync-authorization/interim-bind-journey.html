临时方案-01：用户旅程（登录授权 → 订单绑定 → 结算）
  • 方案要点：授权协议勾选从购买弹窗前移到会员登录页，协议内写明授权用途；订单页仅承担「公域账号绑定」确认；解绑保留在会员中心
  • 会员登录页：展示公域来源（公域账号 B）与登录表单（手机号/验证码/微信一键登录）
  • 授权协议勾选：登录页展示《订单同步授权协议》勾选，未勾选不可登录（临时方案新增位置）
  • 授权用途说明：协议内写明用途——订单同步、公域优惠券发放与核销、售后与会员权益，并可随时撤回/解绑
  • 「登录并同意授权」按钮：勾选协议后可用；登录即完成协议授权，进入订单页
  • 订单页绑定弹窗（自动弹出）：进入订单确认页自动弹出「确认绑定公域账号」，检测当前公域账号 B 征求用户同意（流程与之前一致，此处不重复授权）
  • 账号检测结果：展示检测到的公域账号 B 与来源
  • 「确认绑定」按钮：点击后绑定建立，状态栏更新为「已授权同步」，可正常提交订单
  • 「暂不绑定」：本单订单不同步至公域、不享受公域优惠，可随时「去绑定」补确认

临时方案-02：不一致分支
  • 方案要点：授权已随登录完成；订单页检测到当前公域账号 B 与已绑定账号 A 不一致时，按原流程弹出绑定确认（场景C 逻辑，PRD 5.2）
  • 前置说明：提示登录页协议授权已完成，仅绑定关系待确认
  • 重新绑定弹窗（自动弹出）：展示当前账号 B / 已绑定账号 A 对照
  • 「确认重新绑定」按钮：绑定更新为 B，订单同步至 B，不一致提示消除
  • 「保持原绑定」按钮：绑定不变；本单订单不同步至公域、不享受公域优惠（不回原账号 A），状态栏更新为「不同步」
  • 同步状态栏：随选择更新——重绑后「已授权同步 · 检测一致」；保持原绑定「不同步」
  • 「提交订单」按钮：按绑定状态提示——重绑后同步至 B；未重绑则本单不同步

临时方案-03：会员中心 · 解绑授权关系
  • 方案要点：用户可随时进入会员中心查看授权关系，并对原有授权关系执行解绑（PRD 5.5 / 7.6）
  • 会员信息：展示会员头像与会员号
  • 授权关系卡：展示当前绑定公域账号 B、授权协议 v2.0 与授权用途摘要，标记「已授权」
  • 管理菜单：查看授权协议 / 重新绑定 / 解绑公域账号（需二次确认，危险色标识）
  • 解绑二次确认：说明解绑后果——订单不再同步、公域券可能不可用、历史数据不受影响
  • 「确认解绑」按钮：解绑成功后状态更新并提示影响与恢复路径
  • 恢复路径：重新使用需重新登录授权（登录页协议）并在订单页确认公域账号绑定（PRD 7.6）
